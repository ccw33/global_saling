## 技术实施要点

### 开发规范

#### 代码规范
- **语言版本**: TypeScript 5.x
- **代码风格**: ESLint + Prettier
- **命名规范**: camelCase (变量/函数), PascalCase (组件/类型), kebab-case (文件)
- **注释规范**: JSDoc (仅复杂逻辑)

#### Git 工作流
- **分支策略**: Trunk Based (main分支直接开发)
- **提交规范**: Conventional Commits
- **Code Review**: 可选 (单开发场景)

### 测试策略

#### 单元测试
- **测试框架**: Jest + React Testing Library
- **覆盖率要求**: >= 60% (MVP阶段)
- **Mock策略**: Jest Mock

#### 集成测试
- **测试工具**: Next.js集成测试
- **测试环境**: Docker PostgreSQL

#### E2E测试
- **测试工具**: Playwright
- **测试范围**: 关键业务流程 (购买流程)

### 关键技术决策

#### 决策 1: 本地开发方案
- **选择**: 方案B - PostgreSQL Docker容器 + Next.js本地运行
- **理由**: 不影响现有Nginx服务，开发效率高
- **风险**: 需要Docker环境
- **应对**: 提供Docker安装指南

#### 决策 2: 支付集成顺序
- **选择**: 先实现Stripe，其他支付方式后续
- **理由**: Stripe文档完善，快速验证支付流程
- **风险**: 其他支付方式可能延迟
- **应对**: 预留时间，优先完成Stripe

## 质量保证

### 代码质量标准

- **代码审查**: 单开发场景，自我Review
- **单元测试**: 覆盖率 >= 60% (MVP阶段)
- **静态分析**: 通过ESLint检查
- **性能测试**: Lighthouse Performance > 80

### Bug 处理流程

1. **Bug 发现**: 测试或用户反馈
2. **Bug 报告**: 记录问题到IMPLEMENT_PLAN.md
3. **Bug 修复**: 开发人员修复
4. **回归测试**: 验证修复
5. **Bug 关闭**: 验证通过后关闭

### Bug 优先级定义

| 优先级 | 定义 | 响应时间 |
|--------|------|----------|
| P0 | 阻塞性Bug，无法使用 | 立即 |
| P1 | 重要功能受影响 | 24小时 |
| P2 | 次要功能受影响 | 3天 |
| P3 | 轻微问题，不影响使用 | 下个版本 |
