# AI开发角色协作系统

本项目定义了五个专业角色及其协作工作流，用于AI编码项目的全流程管理。

## 角色列表

| 角色 | 文件 | 类型 |
|------|------|------|
| **产品经理** | `product-manager.md` | manual |
| **架构设计师** | `architecture-designer.md` | manual |
| **开发规划师** | `development-planner.md` | manual |
| **开发工程师** | `development-engineer.md` | always_apply |
| **QA工程师** | `qa-engineer.md` | always_apply |

## 快速开始

### 选择合适的角色

根据任务类型选择对应角色：

- **需求分析** → 产品经理
- **技术架构设计** → 架构设计师
- **开发计划制定** → 开发规划师
- **代码实现** → 开发工程师
- **测试验证** → QA工程师

### 标准工作流程

```
需求分析 (产品经理)
    ↓
架构设计 (架构设计师)
    ↓
开发规划 (开发规划师)
    ↓
代码实现 (开发工程师)
    ↓
测试验证 (QA工程师)
    ↓
验收发布 (产品经理)
```

## 文档规范

每个功能项目需要创建以下文档：

```
docs/feature/<feature>/
├── REQUIREMENTS.md      # 产品需求文档 (产品经理)
├── ARCHITECTURE.md      # 技术架构设计 (架构设计师)
├── IMPLEMENT_PLAN.md    # 开发实施计划 (开发规划师)
└── QA_TEST_PLAN.md      # QA测试计划 (QA工程师)
```

## 核心原则

### 1. 文档先行
- 所有关键决策都记录在文档中
- 文档是角色间协作的主要媒介
- 保持文档的及时更新

### 2. 明确交接
- 每个阶段完成后明确交付物
- 接收方确认理解后再开始工作
- 保持沟通渠道畅通

### 3. 质量门禁
- 每个阶段都有明确的完成标准
- 不达标不进入下一阶段
- 问题及时反馈和解决

### 4. 灵活调整
- 保持计划的灵活性
- 根据实际情况合理调整
- 变更需要沟通确认

## 角色职责简述

### 产品经理
- 需求分析和用户价值定义
- 编写用户故事和验收标准
- 功能验收和发布决策

### 架构设计师
- 技术选型和系统架构设计
- 定义目录结构和技术约束
- 提供技术可行性评估

### 开发规划师
- Epic-Story结构化分解
- 制定开发计划和阶段划分
- 定义验收标准和DoD

### 开发工程师
- 代码实现和单元测试
- Bug修复和代码审查
- 自测和质量保障

### QA工程师
- 测试策略和用例设计
- 执行测试和bug跟踪
- 生成测试报告和质量评估

## 配置说明

### Manual类型角色
需要手动选择激活的角色：
- 产品经理
- 架构设计师
- 开发规划师

### Always Apply类型角色
始终激活的角色：
- 开发工程师
- QA工程师

## 使用示例

### 场景1：新功能开发
1. 产品经理创建 `REQUIREMENTS.md`
2. 架构设计师创建 `ARCHITECTURE.md`
3. 开发规划师创建 `IMPLEMENT_PLAN.md`
4. 开发工程师实现代码和单元测试
5. QA工程师执行测试验证
6. 产品经理确认发布

### 场景2：Bug修复
1. QA工程师提交bug报告
2. 开发工程师分析并修复bug
3. QA工程师进行回归测试
4. 产品经理确认修复

### 场景3：技术重构
1. 架构设计师设计重构方案
2. 开发规划师拆分重构任务
3. 开发工程师执行重构
4. QA工程师进行回归测试
5. 产品经理验收确认

## 质量保障

### 开发工程师质量标准
- [ ] 代码已编写且能编译通过
- [ ] 新功能测试已编写且通过
- [ ] 全量回归测试已运行且通过
- [ ] 代码符合项目约定
- [ ] 无linter/formatter警告

### QA工程师质量标准
- [ ] 测试用例覆盖主要功能路径
- [ ] 测试结果记录详细
- [ ] Bug报告清晰可复现
- [ ] 测试报告完整准确

### 产品经理质量标准
- [ ] 需求描述清晰无歧义
- [ ] 用户故事格式规范
- [ ] 验收标准可测试
- [ ] 功能符合用户预期

## 注意事项

1. **角色边界清晰** - 每个角色专注于自己的职责
2. **沟通及时** - 问题及时沟通，避免信息不对称
3. **尊重专业** - 尊重每个角色的专业判断
4. **以价值为导向** - 所有工作都以业务价值为目标
5. **质量优先** - 不为了速度牺牲质量
